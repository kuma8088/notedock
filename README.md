# NoteDock

NoteDock は、Claude のデスクトップアプリの中でノートを書けるようにするプラグインです。

Code タブでノートのフォルダーを開くと、帯に「ノートを開く」というボタンが出ます。帯は、チャットの入力欄のすぐ上に出る、細長いお知らせの欄です。ボタンを押すと、アプリの右側のブラウザパネル（デスクトップアプリの中で Web ページを表示する画面）にエディターが開き、そのままノートを書けます。

## はじめに

- **これはプレビュー版です。** まだ開発の途中なので、思わぬ動きをすることがあります。
- **最初は、ノートのコピーで試してください。** ふだん使っているノートのフォルダーで、いきなり試すのはやめてください。ただ、Git で管理しているフォルダーなら元に戻せるので、そのままでも大丈夫です。
- 使えるのは、デスクトップアプリの **Code タブ**だけです。Mac と Windows で使えます。

## 必要なもの

- Claude のデスクトップアプリ（Mac か Windows）
- Node.js などを別に入れる必要はありません

エディターは、パソコンの中で動くサーバーを使います。ここでは「エディターのサーバー」と呼びます。このサーバーは1つの実行ファイルにまとめて配っていて、そのファイルを「サーバーの実行ファイル」と呼びます。Mac（Apple シリコン、Intel）と Windows（x64、ARM64）の4種類を用意しています。どこまで動作確認したかは、下の「動作確認した環境」に書いています。

次の環境では使えません。

- Linux と、Windows の中で Linux を動かす仕組み（WSL）
- ターミナルで使う Claude Code だけの環境（ブラウザパネルがないため）

次のフォルダーでも使えません。ノートを入れたフォルダーを開いて使ってください。

- ホームフォルダーそのもの、`/`、`/Users`
- `C:\` のようなドライブのいちばん上と、`C:\Users`
- Windows の、`\\` で始まるネットワーク上の共有フォルダー

## 入れ方

### ふつうの入れ方（claude.ai から入れる）

NoteDock のプログラムは、GitHub のリポジトリ（プログラムを公開している場所）`kuma8088/notedock` で公開しています。claude.ai にこのリポジトリを追加して、NoteDock を入れます。

1. ブラウザで claude.ai を開き、サインインします
2. 「Customize」→「Plugins」→「Add」→「Add marketplace」→「Add from a repository」の順に進みます
3. 「URL」の欄をクリックすると、検索欄が出ます。`notedock` と入力し、出てきた `kuma8088/notedock` を選びます。出てこないときは、`https://github.com/kuma8088/notedock` を貼り付けます
4. 「Sync automatically」はオンのままにして、「Sync」を押します
5. 10秒ほどで、一覧に「Notedock」が出ます。画面では、NoteDock は「Notedock」と表示されます。右の「Add」を押します
6. 「The Notedock plugin includes components that run code」という確認が出たら、「Continue」を押します。この確認が出るのは、NoteDock があなたのパソコンで、毎回たずねずにプログラムを実行するからです。何を実行するかは、下の「安全について」に書いています
7. 「Notedock is installed and ready to use.」と出れば、入っています
8. デスクトップアプリで「Customize」→「Plugins」を開き、一覧に Notedock が出ていることを確かめます。まだ出ていなければ、しばらく待ってから開き直してください
9. 続けて、新しいチャットを開きます

claude.ai で入れたプラグインは、同じアカウントでサインインしているデスクトップアプリにも反映されます。ただ、反映まで少し時間がかかることがあり、その前に始めたチャットでは NoteDock が動かないことがあります。手順8で反映されたことを確かめてから、新しいチャットを開いてください。

上の手順で `kuma8088/notedock` を選べないときは、下の「うまくいかないとき」の zip で入れる手順を使ってください。claude.ai と GitHub を連携していないアカウントで手順3の検索欄がどう出るかは、まだ確かめていません。

Team や Enterprise のプランでは、管理者の設定によって、「Add」の中にプラグインを追加する項目が出ない場合があります。そのときは管理者に聞いてください。

### うまくいかないとき（claude.ai で追加できないとき）

そのときは、プラグインの zip ファイルを直接入れることもできます。

1. GitHub のこのリポジトリのページを開き、「Releases」から `notedock-mod-<バージョン>.zip` をダウンロードします
2. デスクトップアプリで「Customize」→「Plugins」→「Add」→「Upload plugin」の順に進みます
3. ダウンロードした zip を選び、「Upload」を押します
4. 新しいチャットを開きます

入れたあと、プラグインの画面に「Can run code without asking」と表示されます。NoteDock は、あなたに毎回確認せずにプログラムを実行するからです。何を実行するかは、下の「安全について」に書いています。

### 入ったかどうかの確認

- 「Customize」→「Plugins」の一覧に Notedock があれば、入っています
- Code タブでノートのフォルダーを開いてチャットを始めると、帯に「ノートを開く」が出ます

入力欄の「＋」→「Plugins」の一覧には、NoteDock は出ません。入っていないわけではないので、上の2つで確認してください。

### 初めてのフォルダーで使うとき

新しいフォルダーで初めてチャットを開くと、「このフォルダーを信頼しますか（Trust workspace）」と聞かれる場合があります。そのチャットには、NoteDock が読み込まれないことがあります。信頼したあと、もう一度新しいチャットを開いてください。

## 初めて「ノートを開く」を押したとき

初めて押したときだけ、サーバーの実行ファイルを GitHub からダウンロードします。サイズは約80MB で、OS や CPU の種類によって少し違います。ダウンロードが終わるまで、帯に「準備しています…」と出ます。

- ダウンロードするのは、このリポジトリの Releases に置いたファイルだけです
- ダウンロードしたあと、ファイルの中身が正しいかをハッシュ値（SHA-256）で確認します。ハッシュ値は、ファイルの中身から計算する値で、中身が1文字でも違えば、まったく別の値になります
- 正しい値は NoteDock の中に書いてあります。合わなければ、そのファイルは使わずに削除します
- ダウンロードのとき、GitHub には、あなたの IP アドレスが伝わります。作者には届きません。作者に見えるのは、GitHub が出すダウンロード数の合計だけです

入れただけでは、何もダウンロードしません。「ノートを開く」を押したときに初めてダウンロードします。

一度「ノートを開く」を押したフォルダーでは、次からチャットを始めたときに、エディターのサーバーが自動で起動します。押していないフォルダーでは、ボタンを出すだけで、何も起動しません。

## 更新のしかた

claude.ai から入れた場合は、次の手順で更新します。

1. ブラウザで claude.ai を開き、「Customize」→「Plugins」→「Add」→「Manage marketplaces」の順に進みます
2. 「Manage marketplaces」の一覧に出る `notedock` の右の「…」を押し、「Check for updates」を選びます
3. 画面の右下に「Updated to …」と出れば、claude.ai 側の更新は済んでいます
4. 更新がデスクトップアプリに反映されるまで、しばらく待ちます。作者が試したときは、7分から26分かかりました
5. デスクトップアプリで新しいチャットを開き、「ノートを開く」を押します
6. 新しいバージョンに切り替わらないときは、もう一度「ノートを開く」を押してください

手順3のあと、claude.ai の「Customize」→「Plugins」で Notedock を開くと、新しいバージョン番号（たとえば 0.1.0）が出ます。

手順5で「ノートを開く」を押すと、古いバージョンのサーバーが止まり、新しいバージョンのサーバーに切り替わります。新しいバージョンの実行ファイルは、このボタンを押したときにダウンロードされます。そのため、新しいチャットを開いただけでは切り替わらず、「ノートを開く」を押したときに切り替わります。

更新の前に、エディターで書いた内容が保存されているか、確かめてください。保存していない書きかけがサーバーの切り替わりでどうなるかは、まだ試していません。

「Sync automatically」をオンにしていても、デスクトップアプリに新しいバージョンが自動で入るとは限りません。新しいバージョンが出たときは、自動で入るのを待たずに、上の手順で更新してください。

ここからは、作者が実際に試したときの記録です。claude.ai で更新したのは1回だけで、そのあと Mac と Windows のデスクトップアプリで、それぞれ切り替わるかを確かめました。

- 「Check for updates」を選んだあと、「Manage marketplaces」の一覧の `notedock` の行に「1 notice」と表示されました。開くと「Executable files or settings may differ …」という注意が書いてありました。その注意は気にせず手順を続けたところ、切り替わりました
- 「Check for updates」を選んでから、更新がデスクトップアプリに反映されるまで、Windows で約7分、Mac で約26分かかりました
- Windows では、デスクトップアプリの「Customize」→「Plugins」で Notedock を開いたままにしていたところ、更新が反映されたあとも、古いバージョン番号が出ていました。開き直せば番号が変わるのかは、確かめていません。デスクトップアプリで更新が反映されたかを見分ける方法も、まだ分かっていません
- Mac では、1回目に「ノートを開く」を押したときは切り替わらず、数分後に押し直した2回目で切り替わりました。1回目に押したのは、作者が作業に使っている AI がアプリの外から開いたチャットです。そのチャットをデスクトップアプリで開いて、すぐに押していました。原因は分かっていません。Windows では、デスクトップアプリの「New」から開いたチャットで押したところ、1回で切り替わりました
- 手順2の「…」の中にある「Sync automatically」という設定は、入れるときの手順どおり、オンのままにしていました。ただ、約8時間半たっても、デスクトップアプリに新しいバージョンは入りませんでした。オフのときと違いがあるかは試していません
- Mac では、作者の環境で、古いバージョンのエディターを開いたままにしていました。ページを再読み込みしなくても、そのまま新しいバージョンのサーバーにつながっていました。ただ、このエディターは「ノートを開く」から開いたものではなく、作者が作業に使っている AI が、一度だけ使える鍵の付いたリンクで開き直したものです
- Windows では、古いバージョンで始めたチャットを開いたまま、3分ほど様子を見ました。サーバーが二重に起動することも、止まって再起動することもありませんでした。ただ、そのチャットのブラウザパネルには、エディターのタブが残っていませんでした。いつからそうだったのか、更新が原因かどうかは分かっていません
- 古いバージョンの実行ファイルは、切り替わってから2分以内になくなっていました

zip ファイルから入れた場合の更新のしかたは、まだ確かめていません。

変わったところは [CHANGELOG.md](CHANGELOG.md)（変更履歴）に書いてあります。

## 削除のしかた

1. 「Customize」→「Plugins」を開きます
2. NoteDock の「…」を押し、「Remove」を押します

削除したあとに始めたチャットから、NoteDock は読み込まれなくなります。

## 削除しても残るもの

NoteDock を削除しても、データフォルダーの中身はパソコンに残ります。データフォルダーは、NoteDock が自分のファイルを置くフォルダーです。設定、ノートのバックアップ、サーバーの実行ファイル、エディターのチャット欄での会話の記録などを置いています。チャット欄は、エディターから Claude にメッセージを書く欄です。データフォルダーの場所は次のとおりです。

- Mac：`~/Library/Application Support/NoteDock`
- Windows：`%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\NoteDock`

Windows のデスクトップアプリは、Microsoft Store のアプリと同じ方式で入っています。そのため、NoteDock が `%LOCALAPPDATA%\NoteDock` に書いたものを、Windows が上の場所に移して保存します。エクスプローラーで探すときは、上の場所を見てください。

| 残るもの | データフォルダーの中の場所 | 残る日数 |
|---|---|---|
| ノートのバックアップ | `backups` | 種類によって1〜30日（下に書きます） |
| エディターのチャット欄の会話の記録（最近の20件） | `vaults` の中の各フォルダーの `chat-log.json` | 削除するまで残ります |
| エディターのチャット欄に貼った画像 | `vaults` の中の各フォルダーの `chat-images` | 7日 |
| 設定（見た目、フォルダーごとの設定、一度開いたフォルダーの一覧） | `appearance.json`、`opened.json`、`vaults` の中の各フォルダー | 削除するまで残ります |
| サーバーの実行ファイル（約80MB） | `bin` | 新しいバージョンが起動すると、古いバージョンの分は削除されます |

`vaults` の中には、ノートのフォルダーごとに1つずつフォルダーがあります。

バックアップの残る日数は、種類によって違います。

- 保存で上書きされる前の内容は、1日残ります
- 保存のとき、前にこの種類のバックアップを取ってから5分以上たっていれば、上書きされる前の内容を別に取っておきます。これは7日残ります
- ほかのアプリの変更と競合したときなどに、上書きで消える側の内容を取っておいたバックアップは、7日残ります
- その日に初めて書き換える前の内容は、30日残ります

ほかにも、次のことに気をつけてください。

- バックアップと会話の記録は、暗号化していません。ふつうのファイルとして読めます
- 表の日数どおりに古いものを削除するのは、NoteDock が動いているあいだだけです。NoteDock を削除したあとは、古くなっても消えません
- 下書きは、ブラウザパネルの中にも残ります

データフォルダーを消すときは、次のようにします。

1. デスクトップアプリを終了します（エディターのサーバーが止まります）
2. データフォルダーを、フォルダーごとゴミ箱に入れます
   - Mac：Finder のメニューの「移動」→「フォルダへ移動…」を選び、出てきた欄に `~/Library/Application Support` を貼り付けて開き、中の NoteDock のフォルダーをゴミ箱に入れます
   - Windows：エクスプローラーのアドレス欄に `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local` を貼り付けて開き、NoteDock のフォルダーを削除します

データフォルダーを消しても、ノートそのものは消えません。ノートは、あなたのノートのフォルダーの中にあります。

## 消したノートの行き先と戻し方

エディターでノートを削除すると、すぐには消えずに、次の場所へ移ります。

- **Mac**：Mac のゴミ箱に入ります。戻すときは、Finder でゴミ箱を開き、ノートを選んで「戻す」を押します。この機能は、Mac に標準で入っている `/usr/bin/trash` というコマンドを使います。このコマンドは macOS 15 から入っているので、それより古い macOS では削除できません（ノートはそのまま残ります）
- **Windows**：ノートのフォルダーのすぐ下にある `.trash` というフォルダーに移ります。中のフォルダー構成は、元のフォルダーと同じです。戻すときは、エクスプローラーでそのノートを元の場所に移します。`.trash` の中身は自動では消えないので、要らなくなったら自分で削除してください

Windows のごみ箱を使わないのは、ファイルが大きいときなどに、確認なしで完全に消してしまう場合があるからです。

## 困ったとき

### 「ノートを開く」が出ない

- NoteDock を入れたあと、新しいチャットを開きましたか。入れる前から開いていたチャットには出ません
- 入力欄の「＋」→「Plugins」の一覧には、入っていても NoteDock は出ません。入っているかは「Customize」→「Plugins」の一覧で確認してください
- 初めてのフォルダーで「このフォルダーを信頼しますか（Trust workspace）」と聞かれたチャットでは、出ないことがあります。新しいチャットを開いてください
- Claude の設定で `disableAllHooks` を `true` にしていると、プラグインのフック（自動で動く処理）がすべて止まり、NoteDock も動きません。設定ファイル（`~/.claude/settings.json` など）を確認してください
- ホームフォルダーそのものやドライブのいちばん上などでは使えません。ノートを入れたフォルダーを開いてください
- 会社などで管理されているアカウントでは、管理者の設定でプラグインが止められている場合があります

### 「このパソコンでファイルの指紋を調べられません」と出る

この表示の「指紋」は、上で説明したハッシュ値のことです。ハッシュ値の計算には、Mac では `/usr/bin/shasum`、Windows では `certutil.exe` を使います。どちらも OS に標準で入っているコマンドです。この表示が出るのは、ウイルス対策ソフトや会社の設定で、これらのコマンドが止められているときです。パソコンの管理者に聞いてください。

### 「NoteDockのサーバーを起動できませんでした」と出る

このメッセージのあとに、かっこで理由が出ます。

- まず、そのフォルダーのチャットをすべて終わらせてから、新しいチャットを開き、「ノートを開く」を押し直してください。いちばん確実なのは、デスクトップアプリを終了して、もう一度開くことです（終了すると、ほかのフォルダーのチャットも終わります）
- 「Vaultの場所が使えません」と出たときは、開いているフォルダーが NoteDock の使えない場所（ホームフォルダーそのものなど）になっていないかを確認してください。Vault はノートのフォルダーのことです
- ウイルス対策ソフトが、ダウンロードしたサーバーの実行ファイルを止めていることもあります
- 直らないときは、デスクトップアプリを終了し、データフォルダーの中の `bin` を削除してから、もう一度「ノートを開く」を押してください。サーバーの実行ファイルをダウンロードし直します

### サーバーが止まったとき

エディターの画面に「サーバーにつながっていません」と出ます。書いた内容は、下書きとしてブラウザパネルに残っています。そのフォルダーのチャットが1つでも開いていれば、サーバーはすぐに起動し、エディターが再接続したところで保存します。そのフォルダーのチャットが1つも開いていないあいだ、またはデスクトップアプリを終了しているあいだは、エディターは使えません。そのフォルダーでチャットを開いてください。

## 安全について

### プラグインは、あなたと同じ権限で動きます

Claude のプラグインは、パソコンを使っているあなたと同じ権限で動きます。動ける範囲をしぼる仕組みはありません。入れるなら、このリポジトリのコードと作者を信用することになります。気になる人は、コードを読んでから入れてください。

NoteDock が使っているプラグインの機能は、次のとおりです。

| 機能 | 何に使うか |
|---|---|
| 帯とボタン | 「ノートを開く」などのボタンと、今の状態を出す |
| コマンド `/note` | エディターを開くリンクを出す |
| Claude にメッセージを送る | 「ブラウザパネルでエディターを開いて」と頼む。エディターのチャット欄に書いたメッセージを送る |
| チャットの会話を読む | エディターのチャット欄に、最近の会話を並べる |
| ツールを追加する | Claude に頼んで、エディターの見た目やフォルダーごとの設定を変えられるようにする。あなたが頼んだときだけ使う |
| ファイルを読む・書く | データフォルダーの中に、設定や状態を書く |
| 環境変数（OS が持っている設定の値）を読む | データフォルダーの場所と、OS や CPU の種類を調べる |
| プログラムを実行する | エディターのサーバーを起動する。ほかに、OS に標準で入っているコマンドを実行する |
| 通信する | プラグインの通信の機能でつなぐ先は、パソコンの中のエディターのサーバー（`127.0.0.1`）だけ |

OS に標準で入っているコマンドは、次のことに使います。

- サーバーの実行ファイルのダウンロード（`curl`）
- ハッシュ値の計算（Mac は `shasum`、Windows は `certutil`）
- ダウンロードしたファイルを、実行できるようにする設定

インターネットにつなぐのは、サーバーの実行ファイルを GitHub からダウンロードするときだけです。このダウンロードには、上の `curl` を使います。作者のところには何も届きません。

### エディターのサーバーについて

- このパソコンの中からの接続だけを受け付けます。ほかのパソコンからはつなげません
- 開いているほかの Web サイトからの読み書きは、接続元を確認して断ります
- サーバーを使うには、トークン（サーバーを使うための秘密の文字列）が要ります。トークンは `server.json` に書いてあり、このファイルはデータフォルダーの `vaults` の中に、ノートのフォルダーごとに1つずつあります。Mac では、あなただけが読めるようにしてあります。Windows では、あなたのユーザーフォルダーの中に置くことで守っています
- エディターを開くリンクには、使い捨てのトークン（ワンタイムトークン）が付きます。このトークンは10分で使えなくなります。リンクはチャットの記録に残りますが、一度使ったトークンでは開けません
- ノートに貼ったネット上の画像は、すぐには読み込みません。画像の場所に「外部の画像を表示：」で始まるボタンが出て、それを押したときだけ読み込みます。図の場合は「外部の画像などを読み込む：図」というボタンです。読み込むと、画像を置いているサーバーに、あなたの IP アドレスが伝わります

### 開いているノートを Claude に伝える機能

エディターには「開いているノートをClaudeに伝える」という設定があります。最初はオフです。オンにすると、エディターから Claude に送るメッセージに、開いているノートの情報が付きます。その内容は、チャットに書いたメッセージと同じように Anthropic に送られます。

人からもらったノートには、Claude への指示がこっそり書かれている場合があります。そういうノートを開くときは、オフのままにしてください。

### 共用のパソコンで使うとき

- バックアップ、会話の記録、設定は、暗号化せずにデータフォルダーに置いています
- 同じパソコンのほかのユーザーからは、トークンとフォルダーの権限で守っています
- あなたと同じユーザーとして動くプログラム（ほかのプラグインや、あなたが実行したプログラム）からは守れません。ただ、そうしたプログラムは、もともとあなたのノートを直接読めます

セキュリティの問題（脆弱性）を見つけたときは、[SECURITY.md](SECURITY.md) を見てください。

### ビルドをくり返して同じファイルになるか

リリースのときは、サーバーの実行ファイルを2回ビルドし、同じファイルになったか（ハッシュ値が同じか）を比べます。結果は、Releases のそれぞれのリリースの説明に載せます。この比較は、同じ環境と同じキャッシュ（前にダウンロードしたファイルの置き場）で2回ビルドした結果です。別のパソコンでビルドし直しても同じになるかは、検証していません。

## 開発する人へ

| フォルダー | 中身 |
|---|---|
| `app/` | エディター（サーバーと画面）。`app/public` はビルド済みの画面のファイル |
| `mod/` | プラグイン本体 |
| `.claude-plugin/marketplace.json` | マーケットプレイスの一覧 |
| `.github/workflows/` | 自動テストとリリース |

```sh
cd app
npm ci
npm test
npm run build   # app/public を作り直す。コミットしてある app/public と同じになるはず
```

- 自動テスト（`ci.yml`）は、push と pull request の両方で動くので、同じ変更で2回動くことがあります
- `ci.yml` のテストは Mac で動かしています。Windows 用のサーバーの実行ファイルを GitHub Actions の Windows で動作確認するのは、リリースのとき（`release-server.yml`）だけです
- サーバーの実行ファイルは、Deno（2.9.8）でビルドしています。ビルドするのは `release-server.yml` です

### リリースの順番

サーバーの Releases を公開する前に、`release.ts` を `main` に入れないでください。入れると、更新した利用者のダウンロードが失敗します。

1. サーバーの修正を `main` に入れる
2. サーバーのタグを付けて、`release-server.yml` を動かす
3. サーバーの Releases を公開する
4. `release.ts` と `plugin.json` と `mod/` の修正を同じコミットで `main` に入れ、Mod のタグを付ける

`mod/` を変えるときは、別のブランチで `ci.yml` が通ってから `main` に入れます。`ci.yml` は、`release.ts` と `plugin.json` のバージョンが同じか、`BASE_URL` が `server-v<VERSION>/` で終わっているか、サーバーの Releases の `SHA256SUMS` と `release.ts` のハッシュ値が合っているかを確かめます。
